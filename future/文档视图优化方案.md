# 文档视图（DocsView）优化方案

## 现状分析

DocsView 当前实现了基本的文档浏览功能：左侧导航 + 右侧 Markdown 渲染，功能可用但存在以下可优化点：

### 1. 导航结构硬编码，维护性差

**问题**：导航分类、文档条目全部硬编码在模板中，每新增/删除一个文档都需要手动修改模板，容易遗漏或出错。

**现状**：5 个 `docs-nav-section`，每个 section 内手动列举 `<li>` 条目，共 17 个文档项。

**方案**：将导航结构抽取为数据驱动配置，模板通过 `v-for` 渲染。

```typescript
// 导航配置数据
const navSections = computed(() => [
  {
    title: t('docs.quickStart'),
    items: [{ key: 'quickstart', label: t('docs.quickStart') }]
  },
  {
    title: t('docs.coreFeatures'),
    items: [
      { key: 'basic-usage', label: t('docs.basicUsage') },
      { key: 'interactive', label: t('docs.interactiveMode') },
      { key: 'keyboard-shortcuts', label: t('docs.keyboardShortcuts') },
    ]
  },
  // ...
])
```

模板简化为：
```html
<div v-for="section in navSections" class="docs-nav-section">
  <h3 class="docs-nav-title">{{ section.title }}</h3>
  <ul class="docs-nav-list">
    <li v-for="item in section.items" :class="{ active: currentDoc === item.key }" @click="navigateTo(item.key)">
      <span class="nav-indicator"></span>
      {{ item.label }}
    </li>
  </ul>
</div>
```

### 2. 缺少文档缓存，每次切换都重新 fetch

**问题**：`loadDoc` 每次都 `fetch` 请求文件，已访问过的文档再次打开仍需网络请求，体验卡顿且浪费带宽。

**方案**：增加内存缓存，已加载的文档直接复用。

```typescript
const docCache = new Map<string, string>()

const loadDoc = async (docName: string) => {
  // 优先读缓存
  if (docCache.has(docName)) {
    renderedContent.value = docCache.get(docName)!
    isLoading.value = false
    return
  }
  // ... 原有 fetch 逻辑
  const markdown = await response.text()
  const html = marked(markdown)
  docCache.set(docName, html)
  renderedContent.value = html
}
```

### 3. 缺少目录（TOC）自动生成

**问题**：长文档没有快速跳转能力，用户只能滚动查找内容。

**方案**：从 Markdown 渲染后的 HTML 中提取标题，自动生成右侧浮动目录。

- 解析 `renderedContent` 中的 `<h2>` / `<h3>` 标签
- 生成 TOC 列表，点击平滑滚动到对应位置
- 滚动时高亮当前可见的标题项（Intersection Observer）
- TOC 作为右侧浮动面板，窄屏时隐藏

### 4. Markdown 渲染安全性

**问题**：直接使用 `v-html="renderedContent"` 渲染，marked 默认不过滤 XSS，存在安全隐患（虽然文档来自本地，但 changelog 等内容可能包含用户输入）。

**方案**：
- 配置 marked 的 sanitizer 选项，或引入 DOMPurify 做输出过滤
- 给 marked 配置自定义 renderer，为标题添加 id 锚点（同时支撑 TOC 功能）

```typescript
import DOMPurify from 'dompurify'

const renderer = new marked.Renderer()
let headingIndex = 0

renderer.heading = (text, level) => {
  const id = `heading-${headingIndex++}`
  tocData.push({ id, text, level })
  return `<h${level} id="${id}">${text}</h${level}>`
}

marked.setOptions({ renderer })

// 渲染后过滤
renderedContent.value = DOMPurify.sanitize(marked(markdown))
```

### 5. 骨架屏过于简单

**问题**：当前骨架屏只有 1 个标题块 + 3 行文本，与实际文档排版差异大，视觉跳变明显。

**方案**：丰富骨架屏结构，增加代码块、列表等占位元素。

```html
<div class="docs-loading">
  <div class="skeleton-title"></div>
  <div class="skeleton-text"></div>
  <div class="skeleton-text short"></div>
  <div class="skeleton-code"></div>      <!-- 代码块占位 -->
  <div class="skeleton-text"></div>
  <div class="skeleton-list"></div>      <!-- 列表占位 -->
  <div class="skeleton-text short"></div>
</div>
```

### 6. 导航标题与文档显示名重复

**问题**："快速入门" section 下的条目也叫"快速入门"，section 标题和列表项文字完全相同，信息冗余。

**方案**：单条目 section 可以省略 section 标题，直接显示条目；或合并到相邻 section。

### 7. 缺少键盘导航支持

**问题**：没有键盘快捷键支持，用户无法快速在文档间切换。

**方案**：
- `↑` / `↓`：在导航列表中上下移动
- `Enter`：打开选中文档
- `Ctrl+F`：聚焦搜索框（如果添加搜索功能）
- `Backspace`：返回上一个文档

### 8. 缺少文档内搜索

**问题**：无法在文档内容中搜索关键字。

**方案**：
- 在内容区顶部添加搜索输入框
- 使用 `window.find()` 或正则匹配高亮关键词
- 显示匹配数量，支持上/下跳转

### 9. 深色模式下 Markdown 样式适配

**问题**：Markdown 内容的 `:deep()` 样式中部分颜色值可能未完整适配深色主题，如 `blockquote` 的 `accent-light` 背景、`table` 的 `th` 背景等。

**方案**：全面审查 `.markdown-body` 内的 `:deep()` 样式，确保所有颜色都使用 CSS 变量，深浅主题下均可读。

### 10. 导航区域标题全大写显示

**问题**：`.docs-nav-title` 使用 `text-transform: uppercase`，对于中文无效果但会强制英文/日文变大写，与整体界面风格不一致（其他区域已移除 uppercase）。

**方案**：移除 `text-transform: uppercase`，保持与 GeneralSettings 子分区标题风格统一。

| 优先级 | 优化项 | 影响范围 | 复杂度 |
|--------|--------|----------|--------|
| P0 | 导航数据驱动化 | 模板 + 脚本 | 低 |
| P0 | 文档缓存 | 脚本 | 低 |
| P0 | 移除 uppercase | 样式 | 极低 |
| P1 | TOC 自动生成 | 模板 + 脚本 + 样式 | 中 |
| P1 | Markdown 安全过滤 | 脚本 | 低 |
| P1 | 骨架屏丰富化 | 模板 + 样式 | 低 |

| P2 | 键盘导航 | 脚本 | 低 |
| P2 | 单条目 section 优化 | 模板 | 极低 |
| P3 | 深色模式审查 | 样式 | 低 |

## 实施步骤（P0 + P1）

### 步骤 1：导航数据驱动化
1. 在 `<script setup>` 中定义 `navSections` 配置数组
2. 模板中用 `v-for` 渲染 sections 和 items
3. `docPaths` 合并到 navSections 的 item 中，统一数据源

### 步骤 2：文档缓存
1. 添加 `docCache` Map
2. `loadDoc` 中先查缓存，命中直接使用
3. TOC 数据随缓存一起存储（步骤 4 依赖）

### 步骤 3：移除 uppercase + 样式微调
1. `.docs-nav-title` 移除 `text-transform: uppercase`，降低 `letter-spacing`
2. 与 GeneralSettings 的 `.sub-section-header` 风格统一

### 步骤 4：TOC 自动生成
1. 自定义 marked renderer，为标题生成唯一 id
2. 渲染完成后从 renderer 中提取 TOC 数据
3. 右侧内容区添加浮动 TOC 面板
4. Intersection Observer 实现滚动高亮

### 步骤 5：Markdown 安全过滤
1. 安装 `dompurify` 依赖
2. 在 `marked()` 输出后通过 `DOMPurify.sanitize()` 过滤
3. 保留 TOC 需要的 heading id 属性

### 步骤 6：骨架屏丰富化
1. 增加代码块和列表占位元素
2. 调整动画延迟，使逐行出现更自然
