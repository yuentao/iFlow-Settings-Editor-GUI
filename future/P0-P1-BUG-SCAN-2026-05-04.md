## P0 (Critical) — 1 个

### P0-1: `open-external` IPC handler 缺少 URL 协议校验 — 安全漏洞

**文件**: `src/main/ipc/index.js`

**问题**: `open-external` handler 接受任意字符串直接传给 `shell.openExternal()`，没有校验 URL 协议。攻击者若在渲染进程实现 JS 执行（如通过 v-html XSS），可调用：

```javascript
window.electronAPI.openExternal('file:///C:/Windows/System32/cmd.exe')
```

在 Windows 上 `shell.openExternal('file:///...')` 会用默认程序打开文件，可能启动可执行文件。

**对比**: `window.js` 中的 `setWindowOpenHandler` 正确校验了协议：
```javascript
if (url.startsWith('http://') || url.startsWith('https://')) { ... }
```

**修复**: 已完成 — 添加 `http://`/`https://` 协议校验：
```javascript
ipcMain.handle('open-external', async (event, url) => {
  try {
    if (typeof url !== 'string' || !(/^https?:\/\//i.test(url))) {
      return { success: false, error: 'Only http:// and https:// URLs are allowed' }
    }
    await shell.openExternal(url)
    return { success: true }
  } catch (error) {
    return { success: false, error: error.message }
  }
})
```

## P1 (High Severity) — 4 个

### P1-1: `v-html` 渲染 GitHub Release Notes 未做消毒 — XSS

**文件**:
- `src/components/UpdateNotification.vue:29`
- `src/components/UpdateProgress.vue:49`

```html
<div class="notes-content" v-html="formattedReleaseNotes"></div>
```

Release Notes 从 GitHub Releases 获取（外部源），若 Markdown 包含 `<script>` 标签、`<img onerror=...>` 等 HTML 注入向量，将在 Electron 渲染进程中执行。虽然 `contextIsolation: true` 和 `nodeIntegration: false` 限制了爆炸半径，但攻击者仍可：
- 调用 `window.electronAPI.openExternal()` 打开任意 URL（配合 P0-1 已修复）
- 通过 `fetch()` 向攻击者服务器泄露数据
- 操纵 DOM 欺骗用户

项目未使用任何 DOMPurify 或类似消毒库。

**建议修复**: 安装 DOMPurify，在渲染前对 HTML 进行消毒：
```bash
npm install dompurify
```
```javascript
import DOMPurify from 'dompurify'
// 在渲染 release notes 前
const clean = DOMPurify.sanitize(rawHtml)
```

### P1-3: WebDAV 凭据明文存储在 settings.json

**文件**: `src/main/ipc/cloud.js`

WebDAV 用户名和密码以明文存储在 `~/.iflow/settings.json` 的 `cloudSync.providerConfig` 中。原函数名暗示加密，但实际是空操作。

**修复**: 已完成 — 使用机器级密钥文件方案（不依赖 safeStorage）：
- 在 `~/.iflow/.enc_key` 生成/存储随机 32 字节密钥
- 使用 `CryptoManager.encryptField`/`decryptField`（AES-256-GCM）加密 `password` 字段
- 加密后密码以 `$enc:ciphertext:iv:authTag` 格式存储
- 密钥文件丢失时密码无法解密，需用户重新输入凭据

### P1-4: Windows 上 `fs.renameSync` 可能因 EBUSY/EPERM 失败

**文件**: `src/main/services/configService.js:67`

```javascript
fs.writeFileSync(tmpFile, JSON.stringify(data, null, 2), 'utf-8')
fs.renameSync(tmpFile, SETTINGS_FILE)
```

在 Windows 上，如果目标文件 (`settings.json`) 被其他进程锁定（杀毒软件、Windows Search Indexer、备份工具、云同步客户端），`fs.renameSync()` 会抛出 `EPERM` 或 `EBUSY`。

POSIX 上 `rename()` 可以原子替换已打开的文件，但 Windows 不允许替换正在打开的文件。

**失败流程**:
1. 临时文件写入成功
2. 重命名失败（目标被杀毒软件锁定）
3. 临时文件在 catch 块中被清理
4. 原始 `settings.json` 保持不变
5. 用户的保存操作静默丢失

**建议修复**: 使用重试机制（带退避）处理 Windows 文件锁定：
```javascript
const fs = require('fs')

function renameWithRetry(src, dst, maxRetries = 3, delay = 100) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      fs.renameSync(src, dst)
      return
    } catch (err) {
      if (err.code === 'EPERM' || err.code === 'EBUSY') {
        if (i < maxRetries - 1) {
          const waitTime = delay * Math.pow(2, i)
          require('child_process').execSync(`timeout /t ${Math.ceil(waitTime / 1000)} /nobreak >nul 2>&1`)
          continue
        }
      }
      throw err
    }
  }
}
```

## 附加发现（低优先级但值得注意）

### slugify 不支持日文/韩文字符

**文件**: `src/views/DocsView.vue`

原始正则 `[^\w\u4e00-\u9fff-]` 仅保留 ASCII 字母数字和中文基本区，会删除日文平假名 (`\u3040-\u309F`)、片假名 (`\u30A0-\u30FF`) 和韩文 (`\uAC00-\uD7AF`)。

**修复**: 已完成 — 扩展正则覆盖日文/韩文字符范围：
```javascript
.replace(/[^\w\u4e00-\u9fff\u3040-\u30ff\uac00-\ud7af-]/g, '')
```

### 空 slug 导致 querySelector 异常

如果标题只包含被过滤字符（如 `## !!!`），slug 为空，生成 `<h2 id="">`。`CSS.escape('')` 返回 `''`，`querySelector('#')` 抛出 `SyntaxError`。

**修复**: 已完成 — 空 slug 时回退到 `heading-N` 格式，并在 heading renderer 中转义 HTML 属性：
```javascript
const baseId = slugify(text) || `heading-${headingFallbackIndex++}`
const escapedId = id.replace(/"/g, '&quot;').replace(/</g, '&lt;').replace(/>/g, '&gt;')
```
